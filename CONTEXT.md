# CONTEXT.md — ILDIS Domain Glossary

## Domain

ILDIS (Indonesian Law Documentation Information System) manages legal document metadata for Indonesia's JDIHN (Jaringan Dokumentasi dan Informasi Hukum Nasional — National Law Documentation and Information Network).

## Core Entities

### Document
The central entity. Regulations, monographs, articles, and court decisions share the `document` table. The `tipe_dokumen` discriminator is integer-valued in the application (`1` Peraturan, `2` Monografi, `3` Artikel, `4` Putusan).
- **Peraturan** — Regulation (government rule, law, decree)
- **Monografi** — Monograph (academic/legal text)
- **Artikel** — Article (shorter legal writing)
- **Putusan** — Court decision

`DokumenJdih` is an application model for the same `document` table and is used by the JDIHN feed workflow; it is not a fifth `tipe_dokumen` value.

### Document Lifecycle
The application uses `is_publish` to control publication visibility. The verification flow records a verification note and sets `is_publish = 1` transactionally; unpublish actions also exist. Treat verification and publication as related application behavior, not as a fully documented `draft → published → verified` state machine. Legal standing (berlaku/tidak berlaku, dicabut/mencabut, diubah/mengubah) is separate from publication status.
- **Status Transition** — Changing a regulation's legal standing
- **Verification and Publication** — Verification note plus publication flag (`is_publish`)
- **Attachment Management** — PDF/document file uploads (`DataLampiran`)

### Cataloging
Bibliographic metadata attached to Documents:
- **Subject Tagging** (`DataSubyek`) — Subject records associated with a document
- **Author Tracking** (`DataPengarang`) — Persons or bodies associated with the document; `teu` is also used as a document field
- **Status History** (`DataStatus`) — Audit trail of document state changes

Physical copy tracking (`Eksemplar`) and circulation (loan/return/fines) are present in the current application and must not be treated as deprecated based on this glossary.

### Community
Public-facing interactions:
- **Masukan Masyarakat** — Public feedback/suggestions
- **Buku Tamu** — Visitor log/contact form
- **Feed Generation** — Console commands generate public JSON feed files for external portal consumption. RSS support is not established by the current codebase.

### Access Control
Access control uses Yii RBAC data stored in the database (`auth_item`, `auth_assignment`, and related tables). Role/permission membership is defined in application migrations and configuration; avoid assuming institution-scoping or treating this as a complete role catalog without checking those definitions.

## Key Terms

- **JDIHN** — The national network this system feeds into
- **TEU** — Application field associated with document responsibility/author-body metadata; do not expand the acronym without a verified domain source
- **Lampiran** — Attachment/file upload
- **Subyek** — Subject/topic classification
- **Eksemplar** — Physical copy/exemplar
- **Pembentukan PUU** — Legislation formation process
- **Hasil Uji Materi** — Material test results (constitutional review)
- **Pencabutan** — Revocation (of a regulation by another)
- **Penggantian** — Replacement/amendment

## Existing Architecture Decisions

- Yii2 Advanced Template with backend/frontend/common/console tiers
- ActiveRecord is widely used for application models; console code and migrations also use Query Builder and SQL
- RBAC permissions stored in database (`auth_item`, `auth_assignment` tables)
- Document types are discriminated by integer `tipe_dokumen` values in the shared `document` table (current constants: 1–4)
- Public data exposed via JSON feed files generated by console commands
